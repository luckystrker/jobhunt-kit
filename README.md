# Job Search

Универсальный шаблон поиска работы с агентом: профиль кандидата, проверка резюме,
подбор вакансий через Hirify, сопроводительные письма и локальная история откликов.
Это папка документов и скиллов с небольшими утилитами, без сервера и отдельного приложения.
В шаблоне **нет персональных данных, реальных вакансий и включённой автоматизации**.

## Что внутри

| Скилл | Результат |
|---|---|
| [job-profile](plugins/job-search/skills/job-profile/SKILL.md) | Анкета, подтверждённый профиль и банк ответов |
| [job-resume](plugins/job-search/skills/job-resume/SKILL.md) | Проверка фактов, читаемости, рисков ATS-парсинга и соответствия роли |
| [job-search](plugins/job-search/skills/job-search/SKILL.md) | До 5 новых подходящих вакансий, причины совпадения и история поиска |
| [job-apply](plugins/job-search/skills/job-apply/SKILL.md) | Письмо, согласование, отклик через Hirify либо материалы для ручного действия |
| [job-track](plugins/job-search/skills/job-track/SKILL.md) | История, статусы, Markdown-отчёт и опциональное расписание |

## Начало работы с копией шаблона

Установка одной командой (нужны Node.js 24+ и Git):

```powershell
npx github:luckystrker/job-search init ./my-job-search
```

Команда создаёт папку, устанавливает весь шаблон и Hirify CLI. Затем откройте
`my-job-search` в агенте. Вход в Hirify, заполнение профиля и включение расписания
не выполняются установщиком. Публикация пакета в npm registry для этой команды не нужна.

Повторный запуск той же версии сохраняет локальные данные. Если файл шаблона уже
отредактирован или отличается от устанавливаемой версии, команда остановится до
копирования и назовёт конфликт. Автоматическое обновление с перезаписью не выполняется.
После сбоя установки зависимостей можно повторить ту же команду.

Для ручной установки через клонирование нужны Node.js 24+ и агент с доступом к локальным файлам и терминалу. Python и сервер
базы данных не нужны. Node 24 может показывать предупреждение об experimental SQLite.

1. Скопируйте/клонируйте папку. Выполните `npm ci --ignore-scripts` в её корне.
2. Откройте папку в Codex или Claude Code. AGENTS.md/CLAUDE.md указывают агенту скиллы.
3. Напишите: **«Используй job-profile: инициализируй мой профиль поиска работы»**.
   Агент создаст `local/job-search/` и предложит резюме и анкету по блокам.
4. Когда понадобится Hirify, самостоятельно выполните `npm run hirify -- login`.
   Авторизация не входит в установку. В окружении без браузера используйте HIRIFY_KEY
   через секреты окружения, не в файлах шаблона и не в сообщениях агента.
5. После подтверждения профиля: **«Найди до пяти новых подходящих вакансий»**.
   Затем: **«Подготовь отклик на эту вакансию»** и отдельное подтверждение отправки.

Можно работать в папке без установки плагина. Если нужен именно устанавливаемый пакет:

### Codex

В корне копии репозитория:

```powershell
codex plugin marketplace add .
codex plugin add job-search@personal
```

`personal` здесь — имя включённого repo-каталога `.agents/plugins/marketplace.json`,
а не путь к персональной конфигурации. При конфликте с уже настроенным одноимённым
каталогом сначала выберите уникальное имя для этой копии каталога.
После установки начните новую сессию. Команды зависят от версии Codex; проверены
по локальному `--help`. Установка в текущий аккаунт при разработке шаблона не выполнялась.
[Документация упаковки Codex](https://developers.openai.com/plugins/build/plugins).

### Claude Code

Для текущей сессии из корня репозитория:

```powershell
claude --plugin-dir ./plugins/job-search
```

Вызов: `/job-search:job-profile`. Для постоянной установки можно добавить локальный
каталог через `/plugin marketplace add .`, затем `/plugin install job-search@job-search-template`.
[Документация Claude Code](https://code.claude.com/docs/en/plugins).

### Зависимость Hirify внутри пакета

`plugins/job-search/` самодостаточен: содержит оба manifest, скиллы, шаблоны,
инструкции Hirify, утилиты и package-lock с `hirify-cli@0.4.5`.
После установки плагина агент выполняет setup при запросе инициализации:

```text
node <путь-плагина>/scripts/setup.mjs --data <рабочая-папка>/local/job-search --install-cli
```

Команда устанавливает CLI в локальные данные, не в изменяемый кеш плагина.
Установка плагина сама по себе не запускает npm и не входит в Hirify; автоматический
install-hook не заявлен. Это переносимый явный setup, не зависимость от отдельного
плагина Hirify. Для поиска используется именно CLI, без обязательного MCP-коннектора.

## Данные и управление

```text
plugins/job-search/       переносимый пакет, без данных кандидата
  skills/                пять сценариев для агента
  templates/             пустой профиль, анкета, политика, шаблоны материалов
  references/            правила, источники, формат данных и Hirify
  scripts/               локальный SQLite-трекер и оболочки CLI
local/job-search/         создаётся только при пользовательской инициализации
  profile.json           факты, предпочтения, ответы; источник данных профиля
  profile.md             читаемое представление
  policy.json            бюджеты, режим согласования
  history.sqlite         история поисков, вакансий, откликов и статусов
  resumes/               версии резюме
  materials/             письма, ответы, отчёты проверки и ручные шаги
  reports/latest.md      обзор, построенный из истории
```

Попросите агента: «Покажи историю», «По этой вакансии пригласили на интервью»,
«Покажи вакансии, где нужно моё действие». Трекер обновляет статусы с сохранением
источника; Hirify не сообщает ему автоматически ответы рекрутеров.
Команды для прямого чтения из корня копии:

```powershell
node plugins/job-search/scripts/tracker.mjs --data local/job-search list
node plugins/job-search/scripts/tracker.mjs --data local/job-search history
node plugins/job-search/scripts/tracker.mjs --data local/job-search report
```

История сохраняется локально. Личные данные кладите только в local/; .gitignore
исключает её, ключи, базы и распространённые форматы резюме. Если положить личный
Markdown в другое место, он не будет автоматически распознан как личный.
База не зашифрована; резервируйте всю папку данных при остановленных процессах.

## Правила первого этапа

Поиск ограничен до пяти **новых suitable**, по умолчанию до 100 карточек, 20 полных
чтений, 5 раскрытий и 15 минут; текущие квоты Hirify могут уменьшить эти бюджеты.
Проверка соответствия выполняется агентом по полному описанию и подтверждённому
профилю, а не встроенной моделью скоринга. Все результаты и запросы сохраняются.

По умолчанию каждый отклик согласуется отдельно. Опциональный auto требует явного
разрешения на отправку, фиксированного профиля, срока и дневного предела. Неизвестные
обязательные условия блокируют auto. Режим можно выключить в любой момент.
Изменение профиля/письма аннулирует прежнее согласование. Неопределённый результат
отправки сохраняется и не повторяется автоматически.

Через CLI отправляются выбранный профиль Hirify и письмо. Локальное резюме не
загружается автоматически. Для внешней формы агент готовит ссылку, письмо и ответы,
а пользователь отправляет сам. Планировщик — отдельная настройка по запросу;
[готовый prompt](plugins/job-search/templates/scheduled-search.md) входит в пакет.

## Основания и проверка

Рекомендации по резюме опираются на [Greenhouse](https://support.greenhouse.io/hc/en-us/articles/200989175-Unsuccessful-resume-parse),
[Harvard](https://careerservices.fas.harvard.edu/resources/create-a-strong-resume/) и
[CareerOneStop](https://cloudfront.careeronestop.org/JobSearch/Resumes/ResumeGuide/formatting.aspx).
Источники и границы применения — в [руководстве](plugins/job-search/references/resume-guidance.md).
Универсальный ATS-балл и вероятность найма не вычисляются.

```powershell
npm test
npm run check
```

Тесты используют вымышленные данные во временных папках и подменённый транспорт.
Реальные поиски, отклики, авторизация и расписания не запускаются.
